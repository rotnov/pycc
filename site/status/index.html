What pycc can do today.

pycc is a pre-alpha ahead-of-time compiler for typed Python 3.14. This page separates working, repository-tested behavior from the larger design contract. It is not a release announcement.

Current implementation

A real native-code path exists.

The repository contains a working vertical slice from Python source through parsing, HIR, a type-stage passthrough, MIR, LLVM object generation, host linking, and execution of the resulting native binary.

Language slice Small, explicit surface

Module-level print of an i64 literal, zero-argument function definitions, and explicit zero-argument calls are implemented.

Compiler driver Build, run, version

These commands have slice-level working paths. Other documented CLI commands remain planned.

Portability Five native CI targets

Linux x64/arm64, macOS x64/arm64, and Windows x64 build and test in CI. A macOS arm64-to-x64 cross-host path is verified.

Quality 100% lines and regions

Pull requests must keep the current Rust slice at 100% line and region coverage before the protected branch can merge.

Scope boundary

The full typed-Python promise is still planned.

Strict type enforcement is not implemented yet: pycc_types::check is currently a passthrough. Arithmetic, values flowing through function arguments and returns, control flow, recursion with values, strings, floats, booleans, range, and f-strings remain v0.1 work.

Do not use pycc in production.

Unsupported valid Python may still hit explicit slice-limit failures. The examples on the landing page describe the design target unless they are marked as implemented.

Planned next

Frontend depth is the next compiler slice.

The delivery plan next expands the v0.1 grammar, implements real strict typing and local inference, introduces stable diagnostics, and establishes the frontend performance gate. Code generation breadth and conformance demos follow after that foundation.
