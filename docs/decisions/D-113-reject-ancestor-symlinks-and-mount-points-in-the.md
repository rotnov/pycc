## D-113: Reject ancestor symlinks and mount points in the raw --root CLI argument

- Status: accepted (strengthens D-081 after issue #169 was reopened, mirroring D-081's own precedent of superseding rather than editing D-077 in place)
- Context: the repository owner reopened #169 after a post-merge review of PR #266's fix (merge commit `92afa67`) found D-081's `--root` redirection contract was still incomplete. Two reproductions: (1) an intermediate ancestor symlink -- `real-parent/repo` created, `alias-parent -> real-parent` symlinked, `--root alias-parent/repo` invoked -- slips through because the final `repo` component is a real, non-symlink directory, so the leaf-only `ensure_root_is_a_real_directory` check (D-081's original fix) never inspects the earlier `alias-parent` component; (2) a mounted `--root` leaf is never checked at all, since `ensure_root_is_a_real_directory` validates directory/symlink/reparse state but never calls `os.path.ismount(root)`. Both bypass D-081's fail-closed contract before `.resolve()` erases the evidence in `main()`.
- Decision: add `ensure_cli_root_is_not_redirected(root)` in `scripts/manage_ievo_hooks.py`, called only from `main()` against the raw, unresolved `--root` argument before `.resolve()` ever sees it. It walks every ancestor path component of the caller-supplied path (via `root.absolute()`, which only prepends the cwd for a relative path and never follows a symlink) and rejects a symlink or reparse point anywhere in the chain, then rejects the leaf outright unless it is both a real directory and not a mount point (`os.path.ismount()`). This is deliberately a second, separate function rather than an extension of the existing `ensure_root_is_a_real_directory` helper (unchanged) that every internal lifecycle function (`localize`/`check`/`disable`) and roughly 40 pre-existing tests also rely on directly: those callers' own contract has always been "root is already trusted by the time we receive it," and on macOS every raw tempdir path used by those direct-call tests has a real OS-level symlink ancestor (`/var -> /private/var`) that an ancestor-walking version of the shared helper would incorrectly reject. The raw-`--root`-argument check belongs only at the CLI's own boundary in `main()`, the one place that still sees the argument before any internal function's own, already-narrower contract applies to it. New regression tests cover the symlink/junction reproduction (1) through the real CLI (subprocess, matching D-081's own leaf-symlink test's rationale that the bug lives in `main()`'s argument handling, not in any function a direct unit-test call could reach), on both POSIX and Windows, for both the leaf and the ancestor case; the mount-point reproduction (2) directly against `ensure_cli_root_is_not_redirected` in-process with `os.path.ismount` mocked, since a real mount point cannot be created portably in a test; a direct (non-CLI) call proving `ensure_root_is_a_real_directory`'s own leaf-symlink contract still holds for library callers that bypass `main()` entirely; and the leaf check's non-directory operand independently of its mount-point operand.
- Alternatives: extend `ensure_root_is_a_real_directory` in place to walk ancestors (tried first, reverted -- broke roughly 40 pre-existing tests that call `localize`/`check`/`disable` directly with a raw, unresolved tempdir root, because macOS's own `/var -> /private/var` OS-level prefix is itself a symlink ancestor those tests never intended to exercise). Edit D-081's existing Decision text in place with an addendum (rejected on review -- D-081 itself is a precedent for the opposite convention: it was created to supersede D-077 after adversarial review found D-077 insufficient, rather than rewriting D-077 in place, and this reopened issue is the same situation -- D-081's original leaf-only fix was insufficient, not merely under-documented).
- Consequences: D-081's original entry is left unchanged; a reader following #169's history sees the original (insufficient) fix at D-081 and its actual completion here, matching this project's append-only decision convention. `docs/TESTING.md`'s D-077/D-081 lifecycle-coverage narrative is extended to name the new `--root`-boundary coverage without editing its own prior text out.
