## D-162: Site accessibility gate
- Status: accepted
- Context: The public website (`site/`) must pass Lighthouse mobile accessibility audits and W3C Nu ARIA conformance checks. Issue #199 identified two failing Lighthouse accessibility audits on the mobile search landing page (`aria-allowed-role` from `<article role="listitem">` and `color-contrast` from `--ink-faint: #747973`) plus eight Nu ARIA conformance violations involving `<div aria-label>` without a permitted non-generic role. Prior to this decision, no CI gate protected the site against accessibility regressions. A source-grep-only check was considered but rejected because it cannot validate computed styles (color-contrast) or emulate media features (prefers-reduced-motion), and because Lighthouse's own accessibility audit catches issues that simple pattern matching misses.
- Decision: Add a site accessibility gate with three evaluators, each targeting a distinct accessibility surface: (1) **Lighthouse accessibility** — `scripts/run_pages_lighthouse_accessibility.py` runs Lighthouse 12.8.2 `--only-categories=accessibility` in mobile emulation (412×823, DPR 1.75) against the hermetic local server (`serve_pages_fixture.py`), writing one LHR JSON per canonical page; `scripts/check_site_accessibility.rb` validates that `aria-allowed-role` and `color-contrast` audits pass with score 1 and zero failing items. (2) **W3C Nu ARIA conformance** — `scripts/check_site_aria_conformance.py` parses each served HTML body and rejects any `<div>` carrying `aria-label` or `aria-labelledby` without an explicit non-generic `role` that permits naming. (3) **Reduced-motion computed-style** — `scripts/check_site_reduced_motion.js` uses Puppeteer to emulate `prefers-reduced-motion: reduce` and `no-preference`, reading computed `scroll-behavior` and `transition-duration` to assert that reduced-motion suppresses nonessential motion to ≤ 0.01ms while normal motion remains available under no-preference. The gate is wired into CI as the `pages-accessibility` job, added to `ci-gate.needs` with its result in the fail-closed aggregate condition. The job has `contents: read` permission only, no `continue-on-error`, and is not push-only. The D-103 two-merge staging pattern is used: Merge 1 lands the evaluators, tests, ADR, and inert policy-successor fixtures (including the staged `ci-d199.yml` with the new eight-element ci-gate shape and the staged `pages-performance-manifest.json` with post-fix digests); Merge 2 activates the staged workflow/policy changes together with the HTML/CSS accessibility fixes and matching manifest digest updates, carrying `Fixes #199`. Puppeteer is a CI tool (like `npx lighthouse`), not a site dependency; it is installed via `npx` in the CI job and uses the system Chrome. The gate is protected by the policy-successor manifest and the D-103 audit check.
- Alternatives: A source-grep-only ARIA check was rejected because it cannot validate computed styles (color-contrast), emulate media features (prefers-reduced-motion), or catch the full range of Lighthouse accessibility audit failures that a real browser-based audit catches. Binding the gate only through the path-filtered `pages.yml` workflow (instead of `ci-gate`) was rejected because `pages.yml` is path-filtered and would not run on pull requests that touch only non-site files; `ci-gate` runs on every pull request and provides the fail-closed aggregate that the performance gate already uses. Using `aria-label` removal alone (without adding `role="group"` to `.table-scroll`) was rejected because the table scroll container still needs an accessible name for screen-reader users navigating scrollable regions. Using `role="list"`/`role="listitem"` on the pipeline was rejected because Lighthouse's `aria-allowed-role` audit flags `<article>` with `role="listitem"` as an invalid role combination; replacing with semantic `<ol>`/`<li>` resolves the audit while improving the HTML structure.
- Consequences: The gate adds CI runtime for the Lighthouse accessibility run and the Puppeteer reduced-motion evaluation, but the hermetic local server keeps it self-contained. The pinned Lighthouse 12.8.2 version will need periodic updates, each requiring a new policy-successor activation round. The ARIA conformance evaluator uses Python's `html.parser` rather than a full browser parser, so it catches structural ARIA violations but not computed-style or rendering-dependent issues — those are covered by the Lighthouse and Puppeteer evaluators respectively. The reduced-motion evaluator checks the documented motion surfaces (root scroll-behavior, skip-link and nav-link transition-duration) but does not enumerate every animated element; the CSS `@media (prefers-reduced-motion: reduce)` block with `*::before, *::after` universal selector provides the global override that the evaluator verifies. The three evaluators are deliberately separate: Lighthouse accessibility scoring, Nu ARIA conformance, and reduced-motion computed-style checks each cover a distinct surface and must not be collapsed into a single check.
