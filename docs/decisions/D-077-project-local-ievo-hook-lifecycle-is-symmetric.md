## D-077: Project-local iEvo hook lifecycle is symmetric

- Status: accepted (closes #34; implements D-023's local-hook rollback)
- Context: D-023 deliberately relocates iEvo's generated Claude hooks to ignored `.claude/settings.local.json`, but the paired iEvo disable workflow through v0.61.1 removed entries only from shared `.claude/settings.json` before deleting their scripts. The result was a configured local hook whose target no longer existed and exited 127 on every prompt. Upstream `ievo-ai/skills#446` was later resolved by tracked dispatcher shims in PR #455, but this repository's stricter D-023/D-025 policy still keeps generated hooks local; equivalent project-local Codex wiring belongs in `.codex/hooks.json`.
- Decision: `scripts/manage_ievo_hooks.py` is the repository-owned lifecycle boundary. After an iEvo enable or refresh, `localize` moves only the exact known iEvo Claude hook entries from shared to local settings, deduplicates them with refreshed shared metadata taking precedence over a stale local copy, preserves every unrelated setting and hook (including empty groups/events), restores `.ievo/hooks/` to the machine-local ignore policy if upstream added tracked-shim exceptions, and refuses missing or symlinked targets. It writes the local destination before removing shared entries so an interrupted relocation cannot lose the only hook record. `check --smoke` validates the shared/local split, both ignored client configurations, every generated target, and one synthetic zero-exit invocation per distinct hook script. `disable` first parses every present configuration, removes the exact iEvo entries from shared/local Claude and Codex configuration, and fails before mutation if any managed script remains referenced through an unsupported event or command form, including a separator, shell-escaped, lexical, quoted, case-insensitive, or Unicode-prefixed alias of the managed directory; only then does it delete the three generated hook targets and companions plus their vendored fallback directory. It preserves the tracked `.ievo/evo-auto.flag`, because that file records repository-wide intent and disabling it requires a separate reviewed D-023 rollback. All three operations are idempotent; malformed or unsupported configuration fails before mutation.
- Alternatives: adopt upstream's tracked shims (rejected because D-025 requires a separately registered clean-clone contract and the project intentionally keeps hook execution local); teach contributors to hand-edit local JSON before every disable (rejected because it is neither symmetric nor testable); run generic disable and tolerate stale local entries (rejected because `UserPromptSubmit` turns the resulting exit 127 into a per-prompt failure).
- Consequences: `.claude/settings.local.json`, `.codex/hooks.json`, and `.ievo/hooks/` remain ignored and machine-local while `.ievo/evo-auto.flag` preserves shared corrections-only intent. Required agent-policy discovery exercises a tracked-clean-clone enable/refresh → smoke → disable cycle and covers preservation, refreshed metadata, invalid JSON, effective-ignore ordering, unknown managed-subtree references, symlinked hook/config ancestors, interrupted writes, and repeated operations. Every lifecycle transition, including disable, requires the complete non-conflicting intent before mutation. Future iEvo hook names or event shapes fail closed until the helper and tests explicitly support them.
