## D-054: Recover the D-048 exact-base deadlock with one audited exception

- Status: accepted (executed once for staging PR #119; the exception is closed and normal protection is restored — the "grants no reusable permission" framing in Consequences below is narrowly superseded by [D-125](#d-125-session-driven-temporary-ci-check-relaxation-narrowly-superseding-d-024d-054) for exactly that decision's own session-driven mechanism; this entry's own one-time historical exception is otherwise unchanged)
- Context: D-048 admitted a baseline only from a successful `main` run whose head was the exact pull-request base. The current `main` revision `65d67f30101ea2f051371a059ca1f70e0038e53d` produced no successful run because repeated cross-host measurements triggered the known D-051 false-positive class. The corrected D-051/D-053 trust anchor therefore could not merge: every up-to-date staging PR required `ci-gate`, while `ci-gate` required an artifact that could exist only after a successful run of that exact already-failing revision. Further reruns would select for a convenient host, and weakening the threshold or accepting an older artifact would violate the reviewed performance contract.
- Decision: use D-024's administrator-only emergency path exactly once. After public [incident #125](https://github.com/rotnov/pycc/issues/125) recorded the control, justification, owner, expiry, and rollback, explicit administrator authorization permitted removing only `ci-gate` from the required-status set for at most ten minutes and exactly one merge. Strict up-to-date protection, the base-owned `audit`, administrator enforcement, pull-request review rules, conversation resolution, and the force-push/deletion prohibitions remained enabled. [PR #119](https://github.com/rotnov/pycc/pull/119) merged as `416f626fcd8406cc60781d9415589367d4d9c18a`; an unconditional exit trap immediately restored the app-bound `audit` plus `ci-gate` set, and a full readback verified every protection. The corrected D-051 activation is outside the exception and must pass the restored ordinary controls. The activation removes the D-048 digest and fixture, and its allowlist test rejects their return, so the exceptional condition cannot persist as repository configuration.
- Alternatives: rerun D-048 until a favorable host passes (rejected as selection bias); accept an older or failed-run artifact (rejected because it breaks exact successful-base provenance); lower or skip the greater-than-2% comparison (rejected because it weakens D-044); merge through an undocumented administrator bypass (rejected because D-024 requires a public, scoped, auditable incident); keep `ci-gate` optional through activation (rejected because the paired workflow is designed to pass normal protection without bootstrap state).
- Consequences: the one staging merge is publicly auditable in [#125](https://github.com/rotnov/pycc/issues/125), the temporary control was restored within seconds, and there is no standing bypass, repository variable, reusable fallback, or relaxed threshold. The active paired workflow measures both revisions on one runner and therefore removes the exact-base artifact dependency that caused the deadlock. Any future governance deadlock requires a new incident, new explicit authorization, its own expiry and rollback, and independent evidence; D-054 grants no reusable permission.
