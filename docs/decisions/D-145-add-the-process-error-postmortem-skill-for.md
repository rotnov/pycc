## D-145: Add the `process-error-postmortem` skill for structured process-mistake diagnosis

- Status: accepted
- Context: This repository already has the pipeline pieces for learning from process mistakes: `docs/AGENT_RETROSPECTIVE.md` is a curated journal of process errors with a defined entry format, `.ievo/evolution/project.md` accumulates rules from `Trigger: user-observed mistake` entries, and AGENTS.md's own rule promotes durable lessons into `AGENTS.md`, `docs/DECISIONS.md`, or the owning specification. What is missing is a trigger that fires at the moment a process mistake is made or pointed out — the existing pipeline is reactive and ad-hoc, depending on the agent or user remembering to write a retrospective entry and promote it. A concrete instance surfaced during the #345 run: the session used `sleep 240` to wait on CI instead of `scripts/ci-watch.sh` (the `gha-watch-ci-pr` skill's mechanism), exactly because no skill fired at the CI-wait fork to walk the diagnosis-to-fix loop. The user had to point it out manually. Four earlier entries in `.ievo/evolution/project.md` with `Trigger: user-observed mistake during PR monitoring` show the same pattern recurring — each time the lesson was captured only after a user correction, not by a structured self-diagnosis step.
- Decision: Add a new project-local skill `process-error-postmortem` that fires when the agent catches itself having made a process mistake or the user points one out. The skill walks a structured diagnosis: (1) confirm the event meets the `AGENT_RETROSPECTIVE.md` bar (meaningful time cost or wrong intermediate result, not routine self-correction), (2) classify the root cause as one of four mutually exclusive failure modes — trigger gap (a skill exists but its description did not fire at the fork), content gap (a skill was invoked but its instructions did not cover this case), absence gap (no artifact addresses the situation), or compliance gap (a clear rule existed and was simply not followed), (3) apply the fix directly for process-text edits (SKILL.md, AGENTS.md) or via a dedicated PR for new skills/ADRs, (4) record the entry in `AGENT_RETROSPECTIVE.md` following its existing format, (5) promote the lesson into the owning artifact if it is durable policy. The skill is a regular project-local skill (not alpha): its correctness is inherently model-judgment-based (diagnosing a root cause has no deterministic boolean oracle), so it does not fit the alpha governance apparatus's deterministic-eval model. It is documented in `docs/AGENT_TOOLING.md` alongside the other project-local skills.
- Alternatives: adopt an existing skills.sh skill (`self-improvement` by pskoett logs failures to `.learnings/` files and supports promotion to AGENTS.md; `self-improving-skills` by ShunsukeHayashi runs a 7-step OBSERVE→ANALYZE→DIAGNOSE→PROPOSE→EVALUATE→APPLY→RECORD loop over JSONL execution logs; `review-past-performance` by oleg-koval analyzes the last 24h and proposes fixes) — all rejected because they bring their own infrastructure (JSONL logs, ICM memory, `.learnings/` files) that does not integrate with this repository's existing retrospective pipeline (`AGENT_RETROSPECTIVE.md` + `.ievo/evolution/project.md` + AGENTS.md promotion), and none is triggered at the moment of the mistake itself (they run on a schedule or on explicit request, not as a reflex to a caught error); make the skill alpha with deterministic evals (rejected — the diagnosis step's correctness cannot be checked by a boolean oracle the way `issue_select_higher_ranked` or `next_milestone_loop_continues` can, so forcing it into the alpha eval model would produce a vacuous eval that tests trivia, not diagnosis quality); make the skill auto-fire on every tool call or every turn (rejected — a meta-skill that is always vaguely relevant is one that never fires specifically; the trigger is scoped to the moment a process mistake is recognized, not to every step of every task).
- Consequences: A new skill `.claude/skills/process-error-postmortem/SKILL.md` with a `.agents/skills/` thin pointer is added, documented in `docs/AGENT_TOOLING.md`. The skill is not registered in `validate_agent_assets.py`'s `ALPHA_EVAL_RUNNERS` or `validate_alpha_skill_contracts` (it is not alpha), so those scripts need no change. `docs/SPEC.md`'s DECISIONS.md range extends to D-145. The first retrospective entry recorded under this skill (the `sleep` → `ci-watch.sh` instance from the #345 run) is added to `docs/AGENT_RETROSPECTIVE.md` in this same change. The skill's own description is the trigger — if it does not fire at a real process mistake, that is a trigger gap in the skill's own description and should be sharpened, not left as a silent recurrence.
