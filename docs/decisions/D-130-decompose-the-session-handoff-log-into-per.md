## D-130: Decompose the session handoff log into per-session files

- Status: accepted
- Context: [D-066](#d-066-maintain-an-agent-retrospective-log-and-a-session-handoff-log) established `docs/SESSION_LOG.md` as a single running handoff snapshot, updated at every meaningful checkpoint. By this entry, that file held 38 dated entries across 1791 lines and had grown into the exact kind of shared, ever-growing, must-read-then-append tail this project's other conventions already avoid for machine-local hooks ([D-023](#d-023-shared-auto-evolution-intent-with-local-hook-execution)) and for CI-check relaxation incidents ([D-125](#d-125-session-driven-temporary-ci-check-relaxation-narrowly-superseding-d-024d-054), one incident at a time rather than a standing shared state). The cost was concrete, not hypothetical: this same file's own migration hit a real merge conflict mid-session when a concurrent agent session (this repository routinely runs several independently, per [D-013](#d-013-development-model)) landed its own new entry at the same insertion point at the top of the file within minutes of this session's own commit, and the file's own internal separator convention (a `---` rule between entries) turned out to have been applied inconsistently across its history — some entry boundaries had no rule and, in two places, no blank line at all — a symptom of many independent hands editing one shared tail over time without a structural check catching the drift.
- Decision: replace `docs/SESSION_LOG.md` with a `docs/sessions/` directory holding one file per checkpoint, named `YYYY-MM-DD-NN-<slug>.md` — extending the dated-slug convention this repository already uses for `docs/superpowers/specs/` and `docs/superpowers/plans/` with a two-digit `NN` same-day sequence number (`01` = the day's oldest entry, ascending to the newest), since this project's own history already has dates with many same-day checkpoints (2026-07-26 alone has 14) that a bare date prefix cannot order — a first draft of this migration omitted `NN` and was correctly flagged by review as leaving same-day entries unordered by anything but topic slug. Each file keeps the snapshot shape D-066 already established (status grounded in an inspected commit/PR/CI state, what's in flight, known follow-ups, resume pointers) — only the storage granularity changes, not the content contract. `docs/sessions/README.md` is the one static file in the directory: a purpose statement (mirroring this file's own preamble), never appended to, so it never becomes a second shared mutable tail under a different name. A fresh session resumes by listing the dated entries (excluding `README.md`) sorted by filename — the date-then-`NN` prefix makes lexical order match true chronological order — and reading the most recent few, exactly as a session already discovers the newest file under `docs/superpowers/plans/` via `ls`/`git log` rather than a maintained index. All 42 existing entries were migrated verbatim: a script split the original file on its real entry boundaries (a line matching `## YYYY-MM-DD — ...`, confirmed to be the reliable delimiter once the `---` rule itself proved inconsistently applied) and a round-trip check — reassembling every generated file's header and body with whichever separator style the original actually used at that exact boundary — reproduced the original file byte-for-byte before anything was written or the original deleted; `NN` was then assigned per date group from that same verified top-to-bottom (newest-first) order, so it reflects the file's own real history rather than a guess. Migrated entries whose own body text linked a sibling `docs/` file (e.g. `./AGENT_RETROSPECTIVE.md`, `DECISIONS.md#...`) had those relative links rebased to `../...`, since the file now lives one directory deeper. `docs/DECISIONS.md`'s own D-066 entry is not rewritten (this project's own rule: a new decision supersedes, it does not silently edit, an accepted one) — its Status line gains this narrowing reference, mirroring the D-024/D-125 precedent, while its Decision/Alternatives/Consequences prose stands as the historical record of what was true when D-066 was written.
- Alternatives: keep one shared file but rotate older entries into a second archive file once it exceeds some size (rejected — still one shared mutable tail every session merges into, the exact conflict this decision closes, just with an arbitrary rotation trigger added on top); one file per PR number instead of per dated checkpoint (rejected — several existing entries are not tied to a single PR, e.g. mid-flight status snapshots, blocked-state escalations, and post-merge audits; the dated-checkpoint shape already generalizes to every entry shape actually observed in the migrated history); a maintained index file listing every session file (rejected — this is the shared-mutable-tail problem restated one level up: every session would still need to read and append to the same file, and a stale or conflicting index is worse than no index, since a directory listing is always authoritative and cannot go stale); a database or structured log store instead of markdown files (rejected for the same reason D-078/D-013 already give elsewhere: plain files reviewed like any other documentation change stay simplest-correct and add no new tooling dependency).
- Consequences: `AGENTS.md`'s D-066 section and `docs/SPEC.md`'s session-log table row point at `docs/sessions/` (and its `README.md`) instead of the retired file, updated in this same change. `docs/ROADMAP.md`'s own description of the D-066 tooling and its two specific cross-references into named historical entries are updated to the new paths in this same change; `docs/AGENT_RETROSPECTIVE.md`'s own historical mentions of `docs/SESSION_LOG.md`, and every historical ADR entry's own evidence citations into it (D-109's, D-111's, and others), are left untouched — they are accurate descriptions of what was true and where evidence lived at the time they were written, the same rule that already keeps this file from rewriting its own past entries. A future reference to "the session log" anywhere in the docs means `docs/sessions/`, never the retired file. Concurrent-session write conflicts on the handoff log itself become structurally rare rather than merely less likely: two sessions writing on the same calendar date now collide only if they also independently choose the same topic slug, not merely by both touching the file's shared top.
