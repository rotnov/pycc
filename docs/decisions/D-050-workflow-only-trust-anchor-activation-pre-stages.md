## D-050: Workflow-only trust-anchor activation pre-stages phase-aware status documentation

- Status: accepted (narrow documentation-lifecycle rule for D-048; does not weaken the rule that ordinary implementation changes update their affected documentation in the same commit)
- Context: `docs/ROADMAP.md` and the root README must describe the repository tree in their containing commit, and the public `/status/` page is the documented projection of enforced gates and the next delivery slice, but D-048 deliberately requires the exact-head activation commit to change only `.github/workflows/ci.yml` byte-for-byte from the reviewed fixture. The previously staged roadmap wording named the pre-split workflow as the current state, while the README and website placed the performance gate after code-generation/runtime work. Leaving any of them unchanged in the activation commit would make that commit's documentation false, while editing them there would break the reviewed workflow-only transition and change the head after administrative binding.
- Decision: before finalizing the activation head, land phase-aware repository README, roadmap, and public status wording plus complete negative validator mutations in a separate reviewed prerequisite change. The tracked `ci.yml` selects the current state by byte identity with the pre-split, activation, or steady-state fixture: pre-split means the performance jobs are not active; activation means they are required through `ci-gate` and the activation-only bootstrap path for the first exact-main artifact remains present both before and after that artifact is published; steady state means the jobs remain required with no bootstrap and an unconditional exact-predecessor baseline. Workflow bytes do not encode whether the first artifact has already been published, so current-status wording must not infer that external state. The activation commit remains workflow-only. The cleanup commit replaces this transitional mapping in the README, roadmap, governance, and public status page with direct steady-state claims while it removes the retired fixtures and bootstrap state.
- Alternatives: update status documentation in the activation commit (rejected because the commit would no longer be the exact reviewed workflow-only head); leave pre-split or future-sequencing claims stale until cleanup (rejected because documentation is part of the implementation contract); use a vague statement that does not identify how to determine the active phase (rejected because it would evade rather than satisfy commit-relative status); rewrite D-048 silently (rejected because accepted decisions are superseded or clarified by a new ADR).
- Consequences: README, roadmap, governance, and public status text remain true across the byte-only activation boundary and the later first-artifact publication boundary, the administrator can bind one final workflow-only head, and cleanup remains responsible for simplifying the status text once only the steady-state digest survives. This exception is deliberately transition-specific and is not permission to separate ordinary code and documentation changes.
