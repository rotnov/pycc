## D-127: Autonomous agent operation model

- Status: accepted (recorded by the same pull request that adds AGENTS.md's "Autonomous agent operation" section)
- Context: this repository's explicit purpose (D-013) is to be developed end-to-end by autonomous coding agents, and in practice agent sessions on this project already operate that way — planning, implementing, testing, documenting, reviewing, and merging a task without pausing to ask the repository owner a clarifying question or request approval, resolving genuine judgment forks (a design tradeoff, a policy interpretation, a risk call, whether a review finding is real) by consulting an independent reviewer instead. That behavior was live only as unversioned prose in a session's own working assumptions and, once written down, as a plain `AGENTS.md` section with no ADR — a repository-wide authority and escalation model change (who decides what, and when a human must be asked instead) is exactly the kind of irreversible-ish, project-wide call D-024's own preamble and this file's purpose say belongs in `docs/DECISIONS.md`, not only in prose that could be edited without the same scrutiny. This entry gives that policy a versioned governance record and a stable anchor for AGENTS.md to cite, matching how D-024 already anchors the emergency-bypass rules cited from the same document.
- Decision: agents own the full delivery lifecycle for a task — planning, implementation, testing, documentation, review, and merge — without waiting on the repository owner. An agent does not pause a task to ask the repository owner a clarifying question, request approval, or ask them to pick between alternatives. When a task reaches a genuine fork in judgment, the agent resolves it itself by consulting a stronger independent reviewer (a session's own advisor/second-opinion tool, or an independent review agent) rather than soliciting the repository owner, and records the reasoning and resolution in the relevant ADR, plan, or session log exactly as it would any other decision. The repository owner does not answer prompts as part of normal operation, but may still intervene at any time on their own initiative — reading history, editing files directly, redirecting a task, overriding a decision, or answering if they choose to — and any such intervention always takes precedence over this policy and over an agent's own judgment. This policy carves out its own scope explicitly rather than silently: it does not relax any other rule in AGENTS.md or in an agent's own safety boundaries. Actions that require a human administrator elsewhere in that document — the [D-024](#d-024-protected-main-and-audited-emergency-bypass) emergency path, credential and account actions, and any other action a session's own safety rules reserve for the user — still require the repository owner to act, and an agent still asks before taking them; this policy only removes the expectation of asking before ordinary engineering judgment calls. Separately, to conserve tokens across a long autonomous run, agents compact the session at natural checkpoints (after a pull request merges, after a milestone or task-list item completes, or before starting a substantial new task) rather than letting context grow unbounded, doing so proactively rather than waiting for the context window to force it.
- Alternatives: keep the policy as unversioned `AGENTS.md` prose only (rejected — the finding this ADR resolves is precisely that an authority/escalation model change needs a versioned record with alternatives and consequences considered, not only an instruction agents happen to follow); require the repository owner's explicit sign-off on every judgment fork (rejected — this is the status quo the policy is replacing; it does not scale to an autonomous PR-by-PR delivery cadence and contradicts D-013's own premise that the project is built by autonomous agents against mechanically checkable specs); let each agent session decide its own escalation threshold ad hoc (rejected — inconsistent behavior across sessions is worse than a single documented default, and a written policy is exactly what lets a later session or a human reviewer check whether an agent followed it); route judgment forks through a second AI reviewer chosen ad hoc each time rather than a consistent advisor/independent-reviewer pattern (rejected as an unnecessary extra decision per fork — the D-068 pinned-reviewer precedent already establishes that a consistent, previously-vetted reviewer beats an arbitrary one picked in the moment).
- Consequences: a session working on this repository no longer needs to stop and ask before an ordinary engineering judgment call, which is easier — but every such call now needs its reasoning recorded where a human or later session can audit it after the fact, which is a real obligation, not just a courtesy. The named exceptions (D-024's emergency path, credential/account actions, other user-reserved actions) remain hard stops regardless of how much autonomy this entry otherwise grants, so this decision must never be read as broadening those carve-outs. Because the repository owner's own intervention always takes precedence, this entry can never be used to justify overriding an explicit owner instruction on the theory that "the policy says agents decide" — the policy is a default for the owner's absence, not a ceiling on their authority. Superseding or narrowing this policy later (for example, once a second human maintainer is available and some judgment forks should route to them instead of an independent reviewer) requires a new ADR, not a silent edit to this one or to AGENTS.md's section alone. **Correction (2026-08-05, D-142):** this entry's own Decision paragraph instructed agents to "compact the session at natural checkpoints... doing so proactively rather than waiting for the context window to force it"; `AGENTS.md`'s mirroring bullet spelled that out further as "compact the session (e.g. `/compact` or the client's equivalent)... proactively." Neither can actually be executed: direct research against Claude Code's own hooks documentation confirms hooks are "purely reactive... they cannot initiate compaction themselves," `PreCompact` can only block compaction rather than trigger it, and there is no `settings.json` field, CLI flag, or SDK call for a non-interactive `/compact`/`/clear` — `/compact` is an interactive command intercepted from the human user's own terminal input, not something a running session can invoke on itself by emitting the literal text or by any hook. This project's own `CronCreate`/`ScheduleWakeup` scheduling primitives were also confirmed session-scoped ("jobs live only in this...session... gone when [the session] exits"), so neither spawns a fresh session either — both merely re-enqueue a prompt into the same one. AGENTS.md's line 15 is corrected in the same change that adds this note, redirecting to the mechanism actually available from inside a running session: [D-142](#d-142-issue-implements-step-4-implementation-runs-in-a-dispatched-agent-not-the-orchestrating-sessions-own-context)'s dispatched-agent context isolation for a task's own heavy work. This correction changes no other part of this entry's own scope (judgment-fork resolution via an independent reviewer, the owner-intervention carve-outs) — it corrects only the one clause that assumed an unavailable capability. **Correction (2026-08-21):** this entry's Decision paragraph and `AGENTS.md`'s mirroring bullet both specify how a judgment fork is *resolved* — consult a stronger independent reviewer rather than the repository owner — and where the reasoning is recorded, but neither said anything about how the outcome is *characterised*. A session complied with the rule in full (reviewer consulted, owner not asked, resolution applied) while introducing the result with wording that framed the fork as one it could not settle on its own; the owner corrected the framing, not the action. `AGENTS.md`'s bullet is extended in the same change that adds this note: the consultation *is* the resolution, so it is reported as a decision made, and a fork is never described as awaiting the owner or as open pending their input. This is a reporting clarification within this entry's existing scope, not a narrowing of it — the carve-outs above (D-024's emergency path, credential/account actions, other owner-reserved actions) and the owner's precedence over any agent judgment are unchanged, and would require a new ADR to alter.
