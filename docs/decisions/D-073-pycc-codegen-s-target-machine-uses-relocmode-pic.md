## D-073: `pycc_codegen`'s target machine uses `RelocMode::PIC`

- Status: accepted (surfaced by PR #132's own CI: `native-build-test (ubuntu-latest, x86_64-unknown-linux-gnu)` failed exactly one fixture, `mandelbrot_ascii_produces_a_grid_of_the_expected_dimensions_and_palette`, after the D-073-adjacent `-lm` fixes already resolved every other Linux link failure)
- Context: `compile_to_object`'s `create_target_machine` call used `RelocMode::Default`. On this LLVM/target pairing that resolves to absolute (non-position-independent) addressing on Linux, but Ubuntu's `cc` (GCC) links as a position-independent executable (PIE) by default -- a hardening default, not something this project's linker invocation controls. A small program's `.text`/`.rodata` fits within a PIE's 32-bit-relative addressing envelope regardless, so most fixtures link fine either way; `mandelbrot_ascii`'s larger constant data (its ASCII palette string plus several float literals) pushed at least one relocation past what an absolute 32-bit reloc can express inside a PIE, and GNU `ld` refused with "relocation R_X86_64_32 against `.rodata' can not be used when making a PIE object; recompile with -fPIE" followed by "failed to set dynamic section sizes". macOS and Windows's own native-build-test legs never hit this, because Apple's linker requires PIE unconditionally (silently rejecting or accepting compatible input either way in practice) and this project's Windows path routes through explicit `-target x86_64-pc-windows-msvc` clang/lld-link, whose own default already tolerated `Default`'s output.
- Decision: set `RelocMode::PIC` instead of `RelocMode::Default` for every target this function builds for, unconditionally (no per-OS branch) -- position-independent code is not merely a Linux workaround here, it is the correct steady-state choice, since it is mandatory on macOS, standard on Windows/MSVC, and now effectively required on Linux too given every Tier-1 distribution's PIE-by-default toolchain.
- Alternatives: pass `-no-pie` to the Linux linker invocation instead (rejected -- this only patches `src/main.rs`'s and `pycc_codegen`'s own test helper's two linker invocations; the underlying object file would still carry non-relocatable code, an accident waiting to recur anywhere else the object is ever linked, and some hardened Linux distributions refuse `-no-pie` outright when system libraries are built PIC-only, trading one Linux-specific gotcha for another instead of removing the class of bug). Branch `RelocMode` per target OS (rejected as unneeded complexity -- `PIC` is fine everywhere D-073 checked, so there is no reason to special-case it).
- Consequences: every object `pycc_codegen` emits is now position-independent on every Tier-1 target, closing this exact relocation-overflow failure mode for any future fixture with large enough constant data, not just `mandelbrot_ascii`. No known v0.1 test or acceptance criterion depends on absolute addressing.
