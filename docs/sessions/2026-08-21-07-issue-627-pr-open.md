## What #678 delivers

A `bool` stored into an attribute slot the class declares `int` was written to
the slot as a raw word, without D-141's smallint encoding, while the read path
is type-directed. `True` read back as the smallint `0`; `False` aborted the next
read with `pycc_rt: invalid encoded int word 0x0` (exit 134). The abort is the
stronger half of the premise and was not in the issue as filed.

Fixed in MIR lowering rather than where the issue asked. The issue's first
completion criterion (encode inside `scalar_to_slot_word`) would break the case
that already works: the read side truncates i64 to i8 for a `Ty::Bool` slot, so
a marker written there truncates to a non-zero `i8` and `c.b = False` would print
`True`. `MirStmt::AttrSet` now widens through `MirExpr::IntBoundary` when the
declared slot is `Ty::Int` and the value is `Ty::Bool`. `is_assignable` permits
exactly one scalar widening among concrete scalars, so that is the only mismatched
pair reachable at an attribute store. Recorded as D-187.
