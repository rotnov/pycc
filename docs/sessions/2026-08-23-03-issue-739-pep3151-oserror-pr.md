- What shipped: the real PEP 3151 `OSError` exception hierarchy — `OSError` plus its
  10 direct subclasses (`BlockingIOError`, `ChildProcessError`, `ConnectionError`,
  `FileExistsError`, `FileNotFoundError`, `InterruptedError`, `IsADirectoryError`,
  `NotADirectoryError`, `PermissionError`, `ProcessLookupError`, `TimeoutError`) and
  `ConnectionError`'s own 4 subclasses (`BrokenPipeError`, `ConnectionAbortedError`,
  `ConnectionRefusedError`, `ConnectionResetError`) — as concrete, inheritable,
  raisable/catchable compiler-defined `HirClassDef`s, matching CPython's real
  3-level-deep subclass tree exactly. Reuses D-189's per-class compile-time exception
  type tag infrastructure rather than inventing a parallel mechanism.
  - `crates/pycc_hir/src/exception.rs`: `BUILTIN_EXCEPTION_CLASSES` widened from 7 to
    23 entries (the original 7 unchanged, followed by the 16 new names in a fixed
    order). New `is_flat_builtin_exception_class` distinguishes the original 7
    (still name-resolved via `pycc_mir::exception::resolve_exception_tag`, tag
    `None` on their `HirClassDef`) from the 16 new ones (tag fixed to their array
    index, `Some(7..=22)`). `builtin_exception_parent` is now a real 3-level tree
    match instead of a flat 2-entry one; `builtin_exception_class_defs()`'s MRO
    construction walks it with a `while let` loop instead of a fixed-depth push.
  - `FIRST_USER_EXCEPTION_TYPE_TAG` (derived from the array length) is now `23`
    (was `7`); `MAX_USER_EXCEPTION_CLASSES` is now `233` (was `249`) — both formulas
    unchanged, both values shift automatically with the widened array.
  - `crates/pycc_mir/src/exception.rs`: `resolve_exception_tag` unchanged in logic
    (still only the flat 7), given an expanded doc comment explaining the split and
    the new sync-test relationship with `is_flat_builtin_exception_class`.
  - `crates/pycc_types/src/exception.rs`: `is_unshadowed_builtin_exception` gained a
    conjunct requiring actual class-table presence for any of the 16 new names (the
    original 7 keep name-only resolution) — this is the shadow-gate crash-risk fix
    documented in D-194: widening `BUILTIN_EXCEPTION_CLASSES` also widens the
    blast radius of the existing all-or-nothing shadow gate
    (`module_shadows_builtin_exception_name`), and without this fix an unrelated
    shadowed module could reach `handler_type_tags`'s `.expect()` and panic the
    compiler instead of producing a diagnostic. Regression-tested in
    `tests/issue_739_oserror_hierarchy.rs`.
  - `crates/pycc_types/src/lib.rs`'s `KNOWN_CALLABLE_BUILTINS` is **unchanged** — the
    issue's premise that entries should be removed from it was checked and found
    wrong: it is only consulted as a fallback for unbound call-expression inference
    (e.g. `e = OSError("x")`), which stays a legitimate, separate C0001 gap, distinct
    from the structural `raise`/`except` paths this issue implements.
  - New ADR: `docs/decisions/D-194-fix-a-tree-shaped-builtin-exception-family-tags.md`
    (tag-from-array-index decision, shadow-gate consequence, rejected alternatives),
    indexed in `docs/decisions/README.md`.
  - Docs updated: `docs/PYTHON_STANDARDS.md` (PEP 3151 row — status stays `☐` per

  - Tests: new `tests/issue_739_oserror_hierarchy.rs` (412 lines) — end-to-end CLI
    `build`/`check` integration tests: raising/catching each class, catching via
