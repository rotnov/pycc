### The #585 invariant

The change was planned around a non-obvious interaction: [#585](https://github.com/rotnov/pycc/issues/585)
records that `__set_name__` is untriggerable *because* class-level attribute
assignments are unsupported. #911 removes exactly that precondition, so a naive
implementation would have made a CPython divergence reachable and silent —
pycc accepting `X: SomeDescriptor = ...` in a class body and never calling
`__set_name__`.

It was resolved by rejection rather than by documented divergence: class
attributes are restricted to scalar slot types (`int`/`float`/`bool`/`str`), a
descriptor-valued attribute annotates to `Ty::Instance(...)`, fails that
predicate, and is rejected with `C0001`. The restriction is named in the source
at `crates/pycc_hir/src/class/body.rs`, recorded as **D-224**, carried into
#910's scope so Part 2 cannot quietly reopen it, and `docs/TYPE_SYSTEM.md`'s
`__set_name__` clause — which attributed the untriggerability to the wrong
cause — was rewritten in the same change. An implementer comment was posted on
#585.
