## What shipped

Name-binding and type-checking for `HirExpr::NamedExpr` (`:=`) across every position
`pycc_hir` lowers it into: a bare expression statement, an `if`/`while` test, and nested inside
any other expression shape (call argument, binary/comparison operand, f-string interpolation,
container literal element, subscript/slice, method-call base/argument, generic-class-instantiation
argument, nested inside another walrus's own value). Binding happens on both the ordinary
`check`/`check_and_resolve` path (`collect_named_expr_bindings`, `crates/pycc_types/src/lib.rs`)
and independently on the constraint-solver path used for annotation-free bindings
(`bind_named_expr_targets`, `crates/pycc_types/src/constraints.rs`).

New diagnostic `T0050` restricts a walrus value to `int`/`float`/`bool`/`None` (including
`Optional` of those), since codegen's `NamedExpr`-yielding read is only worked out for those
types' refcount contract. A walrus nested inside a comprehension is out of scope (D-177 `core`
gap), matching CPython's own comprehension-scope-skip semantics.

Conformance fixture `tests/fixtures/pep_0572_walrus.py` and an `#[ignore]`d
`pep_0572_walrus_matches_cpython_3_14_7_byte_for_byte` test in `tests/conformance.rs` (pending a
pinned CPython oracle) are staged. Per D-102, the PEP 572 row in `docs/PYTHON_STANDARDS.md`
stays `☐` until this branch's own CI is observed green on all 5 Tier-1 targets in both build
profiles — this PR does not move the conformance-breadth row/PEP count.

`docs/ROADMAP.md` gained a new paragraph under `## v0.3` documenting the dual pre-pass
architecture, the T0050 restriction, and the comprehension-scope exclusion.
