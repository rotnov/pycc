## What the review loop found after `2026-08-20-04`

The D-014 coverage gate — not the targeted fixture run, which read green
— exposed a real production defect. inkwell's `build_and` and
`build_int_compare` constant-fold while `build_call` does not, so for a
compile-time-constant word all four guard halves fold into a constant
`i1`, leaving a branch whose condition is no longer an SSA definition.
Since every genuine heap-`BigIntObj` word originates in a `build_call`,
a constant word is provably never a heap pointer, and the emitter now
returns early for one. `36e0ca69`.

Two D-068 rounds ran against the pinned local reviewer; 0 P0/P1. Both
round-2 findings were fixed in `b021a5c9`:

1. The emitter's doc comment claimed unconditionally that it leaves the
   builder in a fresh continuation block, which the early return made
   false for one path. Fixed by scoping the *block-split* claim to the
   non-constant path while deliberately keeping the "re-read
   `get_insert_block()` afterwards" *rule* unconditional: a caller cannot
   observe whether a word is constant, so a conditional rule would be
   actively dangerous.
2. The early return was pinned by no test. Confirmed empirically rather
   than assumed — deleting `if word.is_const() { return; }` left
   `cargo test -p pycc_codegen --lib` green at 311 passed. The new pin
   `an_in_range_literal_operand_emits_no_refcount_guard_at_all` was then
   mutation-tested in both directions (early return deleted → rc=101;
   restored → rc=0), because a test that passes in both states pins
   nothing.

A third D-068 round was deliberately **not** run for `3b894631`: it is
whitespace-only `rustfmt` output confined to the two files this branch
already created or edited, and round 2's findings still describe the
current diff.
