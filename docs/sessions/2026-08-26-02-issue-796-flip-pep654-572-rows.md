## CI fix round: llms.txt aggregate byte-budget breach (issue #207)

After the PR (#797) was opened and pushed at `9627a065`, its `build`
(website validation) check failed:

```
llms.txt non-optional expansion is 272945 bytes, exceeding the
270336-byte (264 KiB) aggregate budget (issue #207)
```

This is a genuine, diff-attributable failure, not CI noise: the PR's own
docs growth (2866 bytes added to `docs/PYTHON_STANDARDS.md`, 2701 bytes
added to `docs/ROADMAP.md`) pushed the combined size of the 6
"non-optional" `site/llms-txt-context-manifest.json` documents from
267378 bytes (2958 bytes of headroom against the 264 KiB ceiling at
`origin/main`'s `e77c1b65`) to 272945 bytes (2609 bytes over). No
individual per-resource budget was breached — only the shared aggregate
ceiling across all 6 documents.

Two candidate fixes were weighed: trim the newly added prose back under
budget, or raise `budget_kib` in the manifest. Consulted this session's
own advisor tool for the judgment call per D-127 (an autonomous-operation
fork, not a question for the repository owner): the advisor recommended
trimming, not bumping. `docs/WEBSITE.md` frames the 264 KiB ceiling as a
deliberately "reviewed" bound (issue #207's own bloated-2.17MB-context
motivation), and the two edited matrix rows in `docs/PYTHON_STANDARDS.md`
were the only rows in the ~90-row table inlining a full CI-run/commit/PR
citation directly into the `Test` cell — the same evidence already
existed in policy rule 12's prose below the table and in the new
`docs/ROADMAP.md` narrative paragraph, so the verbose cells were
triple-redundant. Confirmed `scripts/check_conformance_breadth.py`'s
`cited_fixtures()` only extracts backtick `` `...py` `` spans from the
`Test` cell, so shortening the cell's surrounding prose could not affect
which fixtures the checker attributes to a row. A `git log -p` check of
`site/llms-txt-context-manifest.json` showed `budget_kib` has moved
before (D-200, 256→264), but bumping again for this PR would need its
own reviewed decision (an ADR, `docs/WEBSITE.md` update, and a fresh look
at whether the manifest's own negative-control test hardcodes 264) —
out of scope for "flip two conformance rows."

Applied the trim: normalized both matrix-row `Test` cells to bare
`` `fixture_name.py` (rule 12) `` citations, condensed policy rule 12's
flavor prose in `docs/PYTHON_STANDARDS.md` (all issue/PR/run-ID/commit
citations and gap classifications preserved), and condensed the new
"PEP 654 and PEP 572 flipped" narrative block in `docs/ROADMAP.md` to
defer to rule 12 instead of repeating its evidence (row/PEP count
arithmetic and the gap-check bugfix description kept intact, since
`ROADMAP_HEADLINE`/`ROADMAP_FIGURES`/`ROADMAP_PEP_FIGURES` only parse the
bolded headline sentence, not this later prose). Removing 3 lines from
`docs/PYTHON_STANDARDS.md`'s table shifted every later row up by 3 lines,
so every `matrix_line` value in
`tests/fixtures/conformance-breadth-manifest.json` was decremented by 3
to match.

Re-verified after the trim: aggregate llms.txt expansion is now 270246
bytes against the 270336-byte ceiling (90 bytes headroom, computed both

`local_path.stat().st_size` summation against the manifest);
`python3 -B scripts/check_conformance_breadth.py` still reports 38 rows /
39 PEPs; `python3 -B scripts/test_check_conformance_breadth.py` still
