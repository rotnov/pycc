**What happened:** after a fresh P1 inventory and all-open-PR overlap check, selected #241 and reproduced its exact failure on current `main`: an otherwise-valid private helper containing `y: int = x` and called with `True` failed both `check` and `build` with `T0022 expected return bool, got int`. The implementation plan was adversarially reviewed through four rounds and published on the issue ([plan comment](https://github.com/rotnov/pycc/issues/241#issuecomment-5170485819)) before code changed.

The private-helper solver now gives an initialized scalar-annotated target its declared representation while keeping the initializer's inference term independent. Scalar annotation bounds are deferred until all harder call/operator evidence has settled, aggregated per final union-find root, and resolved to the most-specific compatible bound in deterministic order; a second binary-constraint propagation pass carries the selected fallback through expressions. Hard evidence therefore preserves `bool` for the source in `y: int = x`, while a genuinely unconstrained source can still use `int` as a fallback. Conflicting bounds fail deterministically with `T0021`, incompatible known narrowing still reaches final validation as `T0025`, and initializer expressions for which the scalar collector has no term still bind the annotated target while remaining subject to final validation. Compatible re-declarations retain D-074's first-binding representation rule. Non-scalar annotated targets receive local-only unresolved terms, and an inference root joined to one cannot resolve an otherwise-inferred private parameter or return as a container, even through hard call evidence; existing container inference from explicit function-signature evidence remains unchanged.

This closes only the inference bug. The exact `_identity(True)` fixture is compiled but deliberately not executed in the regression suite because [#240](https://github.com/rotnov/pycc/issues/240) separately tracks the backend's existing loss of `bool` identity after an `int`-typed storage boundary; an `_echo(True)` control proves the independently returned source still prints `True`. Value-less annotation initialization remains [#245](https://github.com/rotnov/pycc/issues/245). `docs/TYPE_SYSTEM.md` and `docs/ROADMAP.md` record those boundaries without claiming either adjacent issue is fixed.
