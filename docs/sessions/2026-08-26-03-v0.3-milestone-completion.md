## CI fix round: llms.txt aggregate byte-budget breach

`site/llms-txt-context-manifest.json` enforces a 264 KiB (270336-byte)
aggregate budget across six non-optional documents (`site/index.html.md`,
`README.md`, `docs/SPEC.md`, `docs/ARCHITECTURE.md`,
`docs/PYTHON_STANDARDS.md`, `docs/ROADMAP.md`). The initial ROADMAP.md/
README.md additions pushed the aggregate as far as 2192 bytes over budget.
Following the precedent PR #797 established (trim rather than raise
`budget_kib`), both files went through several rounds of prose compression,
checked after each edit via a small Python snippet summing
`os.path.getsize` against the manifest's declared budgets, converging to
exactly 270336 bytes (zero headroom).

Trimming the README "## Roadmap" paragraph three times tripped
`scripts/check_readme_milestone_projection.rb`'s `EVIDENCE_PROJECTION_BINDINGS`
regexes (`conformance-fib-mandelbrot-tier1`, `cli-spec-diagnostic-match`,
`ci-build-test-coverage-100`) by deleting the specific phrases those
bindings match. Each failure was fixed by restoring the minimal matching
phrase elsewhere while re-trimming, until the validator passed cleanly.

One piece of prose compression was reviewed for unintended content loss
rather than pure wording tightening: the old "later capabilities" list
named `modules/imports` explicitly; the new text instead names "v0.4
(projects & incremental compilation)" as the current milestone, and
`docs/ROADMAP.md`'s own v0.4 section already states "Multi-file, imports,
namespace packages." Imports are not dropped from the projection, only
now attributed to the named milestone that owns them rather than left in
the undifferentiated "later" bucket — judged acceptable given zero bytes
of budget headroom to spend restoring the literal word.
