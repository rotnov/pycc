## What was done

Implemented scoped PEP 435 enum support for the v0.3 milestone. The implementation spans HIR, type checking, MIR, and codegen:

1. **HIR** (`pycc_hir`): `is_enum_base_name` recognizes bare `Enum`; `lower_class` detects enum classes, extracts integer literals into `HirClassDef.enum_members: Vec<(String, i64)>`, rejects invalid forms (non-integer values, duplicates, multiple bases, generics, methods).
2. **Type checker** (`pycc_types`): `AttrGet` on an enum class name resolves known members to `Ty::Instance(class)`; `ForList` intercepts enum iteration in both module-scope (`check_stmt`) and function-scope (`check_stmt_in_function`); `unroll_enum_loops` rewrites enum loops into sequential body copies before MIR.
3. **MIR** (`pycc_mir`): `Color.RED` lowers to a synthetic `MirExpr::Name` global `<Class>.<Member>.enum_member` with type `Ty::Instance(C)`.
4. **Codegen** (`pycc_codegen`): `collect_module_bindings` declares synthetic enum globals; module-init emits per-member singleton allocation (2-slot instance: slot 0 = integer value via `tag_smallint_const`, slot 1 = name string via `emit_string_literal`) before top-level code runs.

## Key decisions

- **D-163**: Enum scoped singleton model — `Enum` is a marker, not a real base; members are compile-time singletons; iteration is unrolled at HIR level.
- Actual integer literals are preserved in `enum_members` (not position-derived), fixing the initial codegen hack.
- Enum init runs before top-level statements (not after), fixing a runtime trap where `print(Color.RED.value)` read an uninitialized global.
