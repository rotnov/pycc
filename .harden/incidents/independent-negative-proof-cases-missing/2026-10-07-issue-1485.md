## What happened

The change exempts a foreign import from the shadow refusal by keying on the statement
span and the try arm. A stray import of the same name sits beside a formed fallback
group, in an `else`/`finally` arm, a non-catching handler, or the same arm twice. That
import is still refused, but only through the span-pair check. No test pinned the
refusal. Every changed line was already covered by other tests, so the 100%
diff-coverage gate passed with the guard's negative side unproven.

Verification showed that every shape was already refused, so there was no soundness
defect. The fix added five HIR unit tests and three CLI tests.

## Why nothing earlier caught it

Line coverage measures execution, not whether each refusal shape is distinguished.
Asking "which negative cases does this exemption have to keep refusing" means reading
the design. Review is the rung that does that, and it did.

## Artefact

None. The new tests now guard each shape independently.
