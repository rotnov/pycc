`handbook.md` is this project's contributor handbook.

We are adding a fourth change class, `security`. A `security` change is like a `feature` in
that it owes a changelog entry, but its entry is formatted differently — it goes under
`## Security` as `- <sentence> (#<pr>, CVE-<id>)` — and it owes exactly one entry, so the
number the verification step asserts for it is `1`.

Write an implementation plan for this change to `plan.md`. The plan must say what to change
and where. Do not edit `handbook.md` — the plan is the whole task. No questions.
