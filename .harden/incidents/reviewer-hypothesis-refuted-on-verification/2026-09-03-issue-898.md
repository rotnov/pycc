## Symptom

The pinned reviewer reported that `Loader::resolve`'s `package_inits` preload
in `src/modules.rs` can invert load order so an import cycle reached
indirectly through a subpackage module escapes detection, and named the shape
it predicted would slip through.

## Disposition

Refuted on verification. The reviewer's own predicted-to-fail fixture was
built (`pkg/__init__.py` importing `a`, `a.py` importing back from `pkg`,
entry importing `pkg.sub.mod`) and `pycc check` reports
`error[E0108]: import cycle: pkg/__init__.py -> a.py -> pkg/__init__.py`,
both via the indirect entry and via a direct `import pkg`. The non-cycle
variant correctly exits 0, and its ordering matches CPython, which also runs
`pkg.sub.mod`'s top level before `pkg/__init__.py` completes.

## Root cause

Unchanged from the topic's earlier files: a read-only reviewer reasons about
ordering from source alone and cannot run the program. A confident,
specifically-shaped hypothesis is still a hypothesis.

## Effect on the termination point

None. The existing discipline — build the reviewer's own predicted-to-fail
fixture before changing code for an ordering or lifetime claim — is what
produced the refutation here, at the cost of two small fixtures. Counter
raised to 4 as evidence that the class recurs at roughly one member per
batch and stays cheap.
