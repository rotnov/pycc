# Incident: reviewer-hypothesis-refuted-on-verification (recurrence 3)

**Date:** 2026-08-22
**Topic:** reviewer-hypothesis-refuted-on-verification
**Verdict:** build nothing — the existing discipline fired and was correct
**Batch:** `.harden/findings/issue-719.jsonl`

## Symptom

All three of the round's findings were `note` severity and none survived
verification as an actionable defect:

- a doc-drift finding named a stale fixture path in the conformance matrix.
  The path is real, but the row it sits on is not an evidence row, and the
  matrix guard documents that a non-evidence row's path is a *planned* path it
  deliberately never asserts. Acting on it in this change would have collapsed
  a two-phase split the governing decision record requires;
- two completeness findings questioned whether individual fixture lines
  demonstrate the feature under test. One was refuted at the tokenizer level:
  the construct's whole point is that the grammar had to disambiguate it
  before any later pass runs, so a later pass cannot bypass it. The other was
  accurate as an observation and not a defect — the line is a deliberate
  differential control named in the plan.

## Root cause

Not a failure, and the same one the two prior entries in this topic record.
The pinned reviewer is a hypothesis generator with read-only tools; it cannot
execute the tree it reviews, so a share of its output is necessarily
unverified prediction. The rule that every finding is verified before it is
acted on is what converts that into signal rather than noise.

One nuance this occurrence adds: a finding can be simultaneously correct and
out of scope. The stale-path finding was true, and acting on it would still
have been wrong, because the phase boundary is itself a policy obligation. The
disposition to record for that shape is neither "fixed" nor plain "refuted"
but carried forward — the finding becomes a stated requirement for the later
phase instead of a change to the current one.

## Termination point

None. Escalating would build a guard against a defence that worked. Recorded
so the counter exists if the *verification* step is ever the thing that fails —
which, across three occurrences, it has not.
