# Incident: out-of-model-input-lands-on-wrong-failure-tier (counter seed)

**Batch:** `.harden/findings/issue-1000.jsonl`, rows 1 and 3 (both `fixed`
in `e798d3f3`).

## Symptom

`scripts/check_decision_immutability.py` parses three external input
families: the CI event JSON, `git diff --name-status -z` records, and blobs.
Two out-of-model shapes landed on the wrong failure tier: a rename record
(unreachable under `--no-renames`, but the branch existed) would have raised
`PlumbingError` (usage, exit 2) on the absent destination path instead of a
violation (row 1); a `pull_request` event without `base.sha` raised an
uncaught `KeyError` (exit 1, the violation tier) instead of a `PlumbingError`
(row 3).

## Root cause

The plan enumerated the handled shapes per input family and named a
fail-closed tier for the diff family only; it was silent on event-JSON field
absence. The implementer wrote an untested branch for a shape the plan
declared unreachable and let the interpreter's default exception through for
a shape the plan never mentioned. Gap type: content (plan) for row 3; a
dead-branch shape for row 1. Batch count: 2, sharing a family but not a
mechanism.

## Termination point

Plan text (`issue-to-plan` step 6 items 4 and 7): per parsed input family,
one out-of-model case naming the exit tier it must land on. Not escalated
now — the reviewer's error-path checklist item is a cheap, proven rung that
caught both in one round. A third member makes the plan-text line the
artefact.
