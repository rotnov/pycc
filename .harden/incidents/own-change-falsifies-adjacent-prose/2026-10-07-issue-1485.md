# Incident: own-change-falsifies-adjacent-prose (issue #1485 batch)

**Batch:** `.harden/findings/issue-1485.jsonl`, rows 1, 2, 5 and 6 (all `fixed`, in
`b799ca50` and `297e5651`). Class size 4 within the batch. This topic already has
eight files, so a textual artefact is ruled out.

## Symptom

The change admits a rebinding of a foreign import's name, but only inside one narrow
`try`/`except ImportError` shape. Four pieces of prose still stated either the old
invariant ("nothing rebinds a foreign name") or a wrong scope for the new exception:

- a `docs/RUNTIME.md` sentence about a handler that only reads the name;
- the new module's own doc on chained assignment;
- a soundness comment in `pycc_types`;
- a MIR comment together with the `TYPE_SYSTEM.md` `object` row.

The reviewer caught the first two in round 1 and the last two in round 2.

## Root cause

This is the topic's known subgroup: semantic claims in prose and comments about an
invariant that the change narrowed. No static gate reads an English sentence that
says "nothing can rebind X". The round-2 members sat in crates the change touched
only lightly, which is why the first edit pass missed them.

## Artefact

None. The pinned review loop caught every member within two rounds, so review stays
the catching rung. The one cheaper move is process, not an artefact: grep the tree
for the invariant's own wording before the first review. Round 2's fix did run that
grep. It found and qualified one more site, the `shadow.rs` doc, which no reviewer
had named.

## Sweep result

A tree-wide grep after `297e5651` for the old wording of the invariant ("rebind",
"single producer", "shadowing a foreign import") over `crates/` and `docs/` found
every remaining occurrence carrying the #1485 qualification or describing a
different scope. Round 3 found no doc drift.
