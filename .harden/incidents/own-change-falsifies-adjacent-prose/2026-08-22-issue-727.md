# Incident: own-change-falsifies-adjacent-prose (recurrence 3)

**Date:** 2026-08-22
**Topic:** own-change-falsifies-adjacent-prose
**Verdict:** build nothing — the existing artefact's blocked-gate analysis already
covers the mechanical subset; these three members are all in the subgroup that

**Batch:** `.harden/findings/issue-727.jsonl`, 3 findings, 1 review round

## Symptom

The #727 change replaced `issue-select`'s step 5 ordering paragraph and added a
fifth eval case. Three pieces of prose elsewhere in the tree asserted the old
state and shipped false until the pinned reviewer caught them:

- `docs/AGENT_TOOLING.md:168` — the `issue-select` narrative still said it
  "scores the survivors by a fixed priority-then-size order", which is now only
  the no-scope branch;
- `docs/AGENT_TOOLING.md:211` — "`issue-select` four" eval cases, falsified by
  the fifth case the same change registered, plus an oracle list missing the new
  oracle;
- `scripts/test_run_alpha_skill_evals.py:412` — a test named
  `test_issue_select_oracle_covers_its_three_scenarios` iterating five cases.

## Root cause

All three are the subgroup recurrence 2's amendment already isolated:
**assertions about another file's contents, including counts.** None is
mechanically checkable — no gate reads an English sentence about an ordering
rule, and no gate reads a number spelled "four" in prose or "three" in an
identifier. Every gate in the set passed green with all three false.

The proximate cause is the edit set: the change's own working list was derived
from the issue's completion criteria, which named the skill, the ADR, and the
machine bindings. `docs/AGENT_TOOLING.md` restates all three and was in none of
them. The test name was already stale before this change and was widened by it,
which is the same failure one step earlier.

## Termination point

`Project rule` candidate, considered and rejected as an artefact: AGENTS.md's
"Keep documentation current" already requires updating all affected
documentation in the same change, and already requires explicitly verifying the
no-impact conclusion rather than defaulting to it. The rule exists; it was not
executed. Adding a second sentence saying the same thing is the failure mode
recurrence 1 was opened about.

## Artefact

**None.** Recurrence 2 identified the only real static rung for this topic
(`cargo doc --document-private-items`) and recorded it as blocked on #687. That
rung would not have caught any of these three members — they are prose in a
Markdown file and a Python identifier, outside rustdoc entirely.

What is worth recording, as a counter rather than a mechanism: a change that
edits a rule with a *named* home should grep the tree for the rule's own name
before it is done. All three members here would have been found by
`grep -rn "issue-select" docs/`, a one-command sweep the change did not run
because the reviewer ran it instead. Review is the right rung; this entry is the
recurrence counter that says how often it is being asked to be.

canonical file and asserts nothing about the ordering.
