# Incident: doc-comment-overclaims-unqualified-scope (fifth occurrence, escalated)

**Batch:** `.harden/findings/issue-695.jsonl`, row 4 — two entries, both
`doc-drift`, both `fixed` in `5447e0f5`.

- A newly written child-module header claimed unqualified that its file holds
  the tests driving a full multi-stage pipeline; its last two tests stop at the
  first stage.
- The round-3 fix's *own* wording named a symbol's clause without the source
  qualifier its adjacent banner carried, so the narrowed claim read as covering
  a distinct sibling clause that lives in another file.

**Why this escalates rather than rewords.** Three prior entries in this folder
all concluded `build nothing` / "review tier stays terminal", on the reasoning
that review keeps catching the class at zero cost. Review did catch it —
5 of 5 rounds. What those entries lacked is the second half of the claim: that
catching it is sufficient. The second entry above is a defect *in the fix for
the first class*. A class whose repair reproduces the class is the evidence
that the review tier is not terminal, and step 4a's rule ("an existing topic
means the artefact chosen last time failed — escalate a rung") applies with
four prior files in this folder.

**Gap type: trigger.** The defence exists and fired; the fork is earlier. The
fork is the moment an extraction authors a child-module header, and nothing at
that moment says the claim must be checked against the file's actual contents
and against its siblings' claims.

**Why not the static rung.** Measured against the tree, with a named
counter-example rather than an assertion:
`crates/pycc_types/src/tests/generic_monomorphization_arms.rs`'s header says
"the `is_assignable` `from == Ty::Param` clause" with **no** line qualifier and
is correct — its wording disambiguates on its own — while its in-file banner
carries `(line 3240)`. Any rule of the form "a header must carry the qualifier
its banner carries" therefore fails a correct file, and that file is frozen
review-complete code this task may not repair. A diff-scoped variant does not
escape it: that file is itself touched by this branch. Banner-uniqueness rules
were measured and rejected too — see the sibling entry
`extraction-splits-one-code-arms-test-set/2026-09-11-issue-695` for the counts.

**Why not the governance file.** Step 4a disqualifies a textual governance rule
outright once a topic holds three or more files; this one holds four. The
pointer is planted *inside the running procedure* at the fork instead, which is
step 3.5's routing for a `trigger` gap.

**Why not the review brief.** `.claude/skills/issue-implement/references/review-brief.md`
carries slots and out-of-scope exclusions, and the reviewer it briefs already
detects this class. Adding a checklist item there strengthens a defence that is
not failing.

## The edit

`.claude/skills/issue-implement/SKILL.md`, appended to the D-185
oversized-file decomposition block (the fork it governs), in full:

> **Every doc comment an extraction writes or leaves behind is part of the
> extraction, not commentary on it.** A module header or section banner
> authored by a decomposition states a scope claim, and that claim is checked
> before the commit against two things: the items the file actually holds now,
> and the claims the sibling files of the same tree make about the same
> subject. Write the narrowest true claim — where a neighbouring arm of the
> same symbol is covered elsewhere, the qualifier that separates the two
> belongs in the prose itself, not only in an adjacent banner, and a claim
> quantified over "every" or "all" is either enumerated or dropped. The same
> check applies to a header rewritten to repair an earlier overclaim: a
> narrowing edit that drops a qualifier its own neighbourhood already carried
> reproduces the defect it was meant to fix. Prose the extraction leaves
> behind in the parent is checked the same way — a comment run whose subject
> moved away re-binds to whatever now follows it.

The closing sentence also absorbs the open
`insertion-retargets-a-doc-comment-run` class (four files, artefact still
unbuilt, gate tracked as https://github.com/rotnov/pycc/issues/677), which
shares this fork exactly.

**Why a weaker version would not do.** Dropping the sibling-comparison clause
leaves the second entry above undetected — that header was true about its own
file and false only against a sibling. Dropping the repair clause leaves the
"a fix reproduces the class" path open, which is the specific evidence that
promoted this class off the review tier.

**Approval.** Recorded here in place of a pause, per the host's D-127
no-questions law and the skill's step-5 unattended path. No pull request is
opened by this run; the commit lands on the existing task branch.

## Sweep result

Enumerated every `*.rs` under `crates/**/src/tests/` — 41 files, all 41 carrying
a `//!` module header (`find crates -path '*/src/tests/*.rs' | wc -l`; an earlier
pass in this session said 37, an undercount from a truncated listing, and the
number is corrected here rather than left standing). Each header was read for
unqualified or quantified scope claims; 20 carry a quantifier (`every`/`all`/
`each`/`both`/`any`). **One hit, unfixable here:**
`crates/pycc_mir/src/tests/slice.rs:3` claims it "Covers every present/absent
combination of the start, stop, and step bounds". The file has six such
combinations; `start+step` and `stop+step` are absent — 6 of 8. It is outside
this task's permitted surface (`crates/` is frozen review-complete code for the
#695 extraction) and outside issue #695's own file set, so it is recorded here
rather than repaired or filed: under D-192's process-observation bar a stale
doc comment that cannot cause an incorrect merge decision or hide a compiler
defect is a journal line, not an issue.

`slice.rs` is the only header whose claim was enumerated against its test
bodies one by one, because its claim is a closed 8-element product a reader can
count. The other 19 quantified headers were read and none contradicted its
file's stated subject, but three of them state claims that are enumerable in
principle and were *not* individually enumerated — `pycc_mir/src/tests/`
`exception.rs` ("`resolve_exception_tag` over every builtin type"),
`collection.rs` ("every internal-error panic their type derivation raises") and
`protocol.rs` ("every false result"). Recording that boundary rather than
asserting a clean sweep: this topic's sibling
`documentation-sweep-stops-at-the-changed-file` already holds eight files, and a
sweep reported as exhaustive when it was a read-through would be the ninth.
