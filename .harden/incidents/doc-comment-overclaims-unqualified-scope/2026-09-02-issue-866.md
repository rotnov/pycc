# Incident: doc-comment-overclaims-unqualified-scope (recurrence 2)

**Date:** 2026-09-02
**Topic:** doc-comment-overclaims-unqualified-scope
**Verdict:** build nothing — review tier is terminal for prose justifications
**Batch:** `.harden/findings/issue-866.jsonl`, finding 2 (doc-drift), round 1

## Symptom

`FrontendFailure::Compile`'s doc comment (`src/frontend.rs`) justified
omitting a runtime non-emptiness assertion partly with "the loops in
`render_all` are correct (render nothing) for an empty list anyway". True
of the loops, false as a claim about the command: an empty list would make
`check` exit 1 with no output, violating `docs/CLI_SPEC.md`'s "exit 1 means
at least one diagnostic". The invariant is guaranteed by construction and
pinned by tests; only the prose was over-broad.

## Root cause

Same shape as the 2026-08-29 singleton: prose accurate for the cases the
author had in mind, stated without the qualifier that bounds it. Nothing
mechanical reads an English justification in a `///` comment; the code and
tests were correct.

## Termination point

Recurrence 2 clears the batch threshold, so the ladder was walked: no
static rung applies (no command distinguishes an over-broad justification
from a correct one), and a rule-tier artefact would restate "do not
overclaim", which the 2026-08-29 entry already shows the reviewer catching
at zero cost. Review tier is the right rung -- the same conclusion
`own-change-falsifies-adjacent-prose` reached at counter 3 (a family
relation, not a member: that topic is prose falsified by the same change;
this is prose over-broad from the start). Counter recorded; a third
recurrence re-opens the question of whether the implementer brief should
carry an explicit "qualify every justification" line.

## Fix (this incident)

Comment tightened in `c5302d00` to state the contract violation an empty
list would cause and that construction, not rendering, guarantees
non-emptiness.
