# Incident: doc-comment-drifts-behind-a-widened-constant-table

**Date:** 2026-08-23
**Topic:** doc-comment-drifts-behind-a-widened-constant-table
**Verdict:** pending (singleton — batch threshold not met, counter seed only)

## Symptom

Batch pass over `.harden/findings/issue-739.jsonl` (2 findings, 1 review
round). One finding: a doc comment on `HirClassDef::exception_type_tag`
(`crates/pycc_hir/src/class.rs`) described a fixed-size builtin exception
table by its pre-change shape and cited its old numeric bounds (the flat-7
count, the tag range starting at 7, the max-user-classes value derived from
it) after the underlying array widened from 7 to 23 entries in the same
change. The doc comment sat one file away from the array it described and
was not touched by the edit that resized the array.

## Root cause

A doc comment that restates a derived numeric fact (a range bound, a count)
in prose, on a different file from the source of truth, has no mechanical
link back to that source — the compiler and the tests are both silent when
the two drift apart. This is the same "outside the frame" pattern the
`documentation-sweep-stops-at-the-changed-file` incident already names
(same journal directory), one file removed: the change resized the array
correctly and updated the tests that exercise it, but a prose description
of the array's shape living on a *different* struct's field doc was not on
the sweep's radar.

## Termination point

Not escalated — singleton, caught by the existing pinned review loop before
merge. No artefact proposed at this occurrence.
