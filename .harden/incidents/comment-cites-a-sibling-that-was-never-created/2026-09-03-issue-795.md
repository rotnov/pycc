# Incident: comment-cites-a-sibling-that-was-never-created (first file)

**Batch:** `.harden/findings/issue-795.jsonl`, row 4 (round 4). Batch-internal
singleton with no journal match, so this entry is a counter seed: no artefact
is proposed and none was built.

## What happened

A rationale comment added by the #795 diff above the
`l0001_return_in_loop_in_except_star` test told the reader to compare it with a
sibling fixture, `c0001_break_in_except_star_inside_a_loop_in_the_clause`, that
exists nowhere in the repository. Round 4 of the pinned review found the
dangling name. Fixed in `63bdad93` by repointing the comment at
`crates/pycc_hir/src/stmt/exception.rs`'s `except_star_context_tests`, which is
where that direction is actually covered.

## Why it was not caught

Distinct from `own-change-falsifies-adjacent-prose`, where prose is true when
written and a later edit falsifies it. Here the comment was false the moment it
was written: it named a fixture the author intended to add and then could not,
because the shielded `break`/`continue` direction *compiles* rather than
producing a diagnostic, so it has no public-CLI fixture by construction. The
comment survived the author's own read because the invented name is
well-formed — it follows the repository's `<code>_<scenario>` fixture
convention exactly, so nothing about reading it suggests it is not real.

Gap type: **absence** at the static tier — no mechanism checks that an
identifier cited inside a comment resolves. Review is currently the only rung
that reads comments at all.

## Artefact

None at a singleton, per the batch threshold. Recording the candidate for
whoever finds this counter next: unlike most doc-drift classes, this one *is*
mechanically decidable. Fixture names follow a fixed, greppable shape, and a
check that every `tests/diagnostics/`-shaped identifier appearing in a comment
resolves to an existing fixture pair or test function is a pure string
predicate with no semantic judgment in it — the sweep under `verify` above is
already a working prototype of it. If a second occurrence lands in this topic,
that is the rung to take, not a rule.
