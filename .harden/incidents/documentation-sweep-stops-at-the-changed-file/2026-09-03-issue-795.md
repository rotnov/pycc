# Incident: documentation-sweep-stops-at-the-changed-file (recurrence 7, eighth file)

**Batch:** `.harden/findings/issue-795.jsonl`, row 3 (round 3). Journal match,
so the class takes the full cycle despite being a batch-internal singleton.

## What happened

The #795 diff changes observable compiler behavior (two new rejections) and
moves conformance-breadth acceptance evidence, and it updated
`docs/PYTHON_STANDARDS.md`, `docs/DIAGNOSTICS.md`, `docs/RUNTIME.md`, the
breadth manifest and a new ADR — but not `docs/ROADMAP.md`. Round 3 of the
pinned review pointed at the roadmap's #382/#540 exception-handling section,
which is maintained as a running series of dated update paragraphs and which
AGENTS.md requires be kept current in the same pull request. Fixed in
`c59bf8b1` by appending one dated `2026-09-03 / #795 / D-222` paragraph in the
form the adjacent D-193/D-202 entries already use, editing no existing
paragraph and moving no matrix row.

## Why it was not caught

A variant this topic has not recorded before. The six earlier entries are
about an *extent* failure — a claim restated in more places than the change
looked at. Here the sweep's extent was fine; what was missed is that a
document can require an addition even when it contains no stale claim at all.
The roadmap section said nothing false before this diff. The implementation's
documentation review asked "which sentences does this change falsify?" and
correctly answered "none in `ROADMAP.md`", when AGENTS.md's actual rule is the
stronger "keep it current whenever behavior or acceptance evidence changes",
which is satisfied only by an addition. Gap type: **trigger** — the existing
sweep habit fires on falsification, and this fork is an omission.

## Artefact and why this type

Build nothing; the ladder for this variant:

- **Static/precommit:** a gate that required a `docs/ROADMAP.md` hunk in every
  behavior-changing pull request is decidable in principle but wrong in
  practice — "behavior-changing" is exactly the judgment the fail-closed CI
  classifier already makes for coverage, and reusing it here would fire on
  refactors and diagnostics-wording changes that genuinely add no roadmap line.
  The false-positive rate is the whole cost, and a gate agents learn to satisfy
  with a filler paragraph is worse than no gate.
- **Textual:** disqualified. Eight files in this topic, and the #729 entry
  already measured a textual rung here at zero.
- **Seam:** no tool-call fact distinguishes a diff that owes the roadmap a
  paragraph from one that does not.
- **Review:** caught it in round 3 at warning severity; the fix was one
  paragraph and the next round was clean on this class.

If the omission variant recurs, the next rung is narrower than a
whole-document gate and mechanical: when a pull request's diff changes a
`tests/fixtures/conformance-breadth-manifest.json` row's `category` or
`status`, require a `docs/ROADMAP.md` hunk in the same diff. That predicate is
exact — it fires only on acceptance-evidence movement, which is the half of
AGENTS.md's rule a machine can actually decide — and it would have fired here.
Recorded, not built: it is its own change, with its own review and a
repository-wide sweep for existing manifest-only commits before it can be
enabled.
