# Incident: documentation-sweep-stops-at-the-changed-file (recurrence 5, sixth file)

**Batch:** `.harden/findings/issue-729.jsonl`, rows 1-2 (round 1-2, comment form)
and rows 4-6 (rounds 3-5, prose form): five `fixed` doc-drift rows, one class.

## What happened

`tests/conformance.rs` was split into a root file plus `tests/conformance/*.rs`
cohorts. Every file the plan named (the three harness text-readers, the ADR,
`docs/TESTING.md`'s new D-221 section) was updated correctly. Five sentences
that *claimed* the tests live in, are run by, or are registered in the single
root file were not: a stale comment inside the root itself, a pointer comment
citing the wrong issue, and one sentence each at `docs/PYTHON_STANDARDS.md:22`,
`docs/TESTING.md:25` and `docs/TESTING.md:181`. The pinned reviewer found them
one per round across rounds 1-5; the round-4 fix's own sweep grepped for the one
exact phrasing it had just corrected (`run directly by`) and so missed the
round-5 sentence (`registered in`).

## Why it was not caught

The `issue-implement` step-5 sentence that the #867/#868 entries planted
("search every spelling, adjudicate every hit") was present on the branch base
and was followed with one spelling. This pile is the measurement those entries
deferred to, and the result is **zero**: the textual artefact was read and did
not change the behaviour. A search for the *claim* rather than the *wording* —
`(run (directly )?by|registered in|declared in|lives? in) \`?tests/conformance\.rs\`?`
over `docs tests scripts`, excluding the dated historical records — returns
exactly the three prose members at the post-split commit and nothing at HEAD.

## Artefact and why this type

Per the ladder, a textual rung that measured zero is escalated, not reworded.
The catchable sub-class is decidable from the tree: when `tests/<x>.rs` gains
a sibling directory `tests/<x>/`, any live-doc or comment predicate that
locates tests in `tests/<x>.rs` without a cohort qualifier is a defect. That
checker is its own change with its own review and repository-wide sweep, so it
is filed as a task rather than built inside the pull request whose review
surfaced this instance (same reasoning as `incident.md`).
