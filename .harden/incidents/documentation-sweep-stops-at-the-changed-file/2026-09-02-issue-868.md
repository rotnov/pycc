# Incident: documentation-sweep-stops-at-the-changed-file (recurrence 4, fifth file)

**Batch:** `.harden/findings/issue-868.jsonl`, rows 2 (round 1), 4-7 (round 2),
8-11 (round 3): eleven `fixed` doc-drift rows, one class.

## What happened

Issue #868 moved the type checker's module-level driver from `lib.rs` into
`module.rs`, deleted `check_with_environment`, and demoted the single-
diagnostic entry points (`check_with_signatures`, `checked_function_signatures`,
`infer_function_signatures_with_solver`) to `#[cfg(test)]` wrappers. Round 1
named ten stale comment sites; the fix round ran the tree-wide search the
#867 entry planted in step 5 — and still needed two more rounds:

- Round 2 (35 sites): the round-1 search adjudicated every hit with the
  criterion "does the name still compile", which the `#[cfg(test)]` wrappers
  satisfy; the right criterion was "does the name exist in a release build, at
  that location, in that role".
- Round 3 (6 sites): the round-2 search matched backticked names only;
  bare spellings, one path-qualified spelling, and "lives in `lib.rs`"
  location claims were outside the pattern.

## Why it was not caught

**Gap type: content.** The #867 pointer fired (a search was run and
recorded, which is what its Proof section asked for) but named neither the
adjudication criterion nor the spellings a search must cover. The mechanical
rung that entry named as next — `scripts/check_harden_findings.py` requiring a
recorded search on every `fixed` doc-drift row — would not have fired here:
every row recorded a search. That rung forces the record, not its quality,
and this occurrence is not evidence for building it.

The static rung that *would* have caught rounds 1 and 2 for Rust comments is
rustdoc's intra-doc-link resolution: a comment that links a symbol as
[`name`] instead of naming it in backticks fails
`-D rustdoc::broken_intra_doc_links` when the symbol is deleted or, because
docs build without `cfg(test)`, demoted to test-only. It would not catch
round 3 (Markdown prose and free-text location claims), which stays at review
tier. Adopting it is a repository-wide convention change (backticks to links
across every crate, a sweep, a CI flag on top of four pre-existing
private-link warnings) with its own review — recorded here as the identified
promotion, not built inside the pull request whose review surfaced this
instance. It fails D-192's filing bar (a doc-drift gate neither causes a wrong
merge decision nor hides a compiler defect), so it is a candidate for the
agent-tooling umbrella issue once one exists, not an issue of its own.

## Artefact and why this type

Same artefact, content edit: the step-5 sentence now names the spellings a
search covers (backticked and bare, path-qualified and unqualified, location
claims naming the old home) and the adjudication criterion (post-change
status in a release build, not "still compiles"), and asks the `note` to
record forms and criterion, not only the hit count. Counter is five files;
the base class (prose outside the diff's frame) is confirmed review-tier and
the reviewer caught every member. This sub-class pointer has failed once
since it was planted, on content it did not carry; the rung above it is the
rustdoc gate above, deferred as described.
