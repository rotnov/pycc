# Incident: documentation-sweep-stops-at-the-changed-file (recurrence 3, fourth file)

**Batch:** `.harden/findings/issue-867.jsonl`, rows 1, 2, 3 (round 1) and 6
(round 2) — the base class, and its fix-round sub-class.

## What happened

Issue #867 moved `lower_checked`'s module walk from `crates/pycc_hir/src/lib.rs`
into a new `module.rs` (`lower_all` + `lower_top_level_item`), keeping
`lower_checked` as a thin wrapper. The new module was documented; about thirteen
comments across nine untouched files in the same crate still attributed the
walk, the dispatch, and the side-table builds to `lower_checked`. Round 1 named
three of them. The fix round (`1ab2431c`) edited exactly those three sites.
Round 2 found the same class at ten more sites; the fix (`0c7946d1`) finally
swept the whole crate with a symbol search and cost one extra review round.

## Why it was not caught

Two layers. The base class is this topic's known one (prose outside the diff's
frame describing the pre-change world). The sub-class — fix extent taken from
the reviewer's enumerated sites — already had a lesson: the 2026-08-29 #784
entry in this topic routed it to `docs/AGENT_RETROSPECTIVE.md`. AGENTS.md
declares that journal informational, not policy, and nothing in
`issue-implement` step 5 pointed at it, so the rule was unreachable at the fork
where the fix round is briefed. **Gap type: trigger**, not compliance.

The pending `precommit` reference-integrity gate this topic's `incident.md`
proposes would not have fired here either: `lower_checked` still exists, so
"path exists / path contains symbol" both pass. Its scope should be read as
"a moved symbol that no longer exists"; a surviving wrapper is out of its
reach. The base class stays review-tier (the reviewer caught every member).

## Artefact and why this type

The rule-audit escalation is one rung above the artefact that failed. The
failed artefact was a retrospective line outside the ladder; the rung above it
is the same rule planted at the fork: the "focused fix" sentence in
`.claude/skills/issue-implement/SKILL.md` step 5 now derives a fix's extent
from the defect (tree-wide search for the phrase or symbol before committing,
every hit adjudicated, search and hit count recorded in the finding's `note`).
Reach is this skill only, which is also the only procedure that runs the fix
round. The next rung, if this pointer fails once more, is mechanical:
`scripts/check_harden_findings.py` requiring a recorded search on every
`fixed` doc-drift row — a forcing function on the record, recorded here, not
built.
