# Incident: paraphrase-of-a-formal-rule-drifts-from-its-source (recurrence 3)

**Batch:** `.harden/findings/issue-423.jsonl`, one class (2 findings, round 1).

## Symptom

Two source comments paraphrased a decision entry and attributed to it content
it does not carry. One named a symbol as withheld "per D-136" that D-136 never
mentions (its addendum lists three other symbols). The other attributed a
rationale to D-112's `Consequences` field when the sentence lives in D-112's
dated update note. Neither sentence was written by this change: both predate
it, and both cited the deleted monolithic decision log, where the claim was
practically uncheckable. Rewriting the path to the decision's own file made
the claim checkable, and the first review round that could open the target
found the drift immediately.

## Root cause

**Gap type: content.** A paraphrase of a decision entry, written from memory of
what the entry says rather than from its text, and never diffed back against
the source. The monolithic log hid this class: a reader following
`docs/DECISIONS.md` landed in a multi-thousand-line file and stopped. A
per-decision file exposes it on the first read.

## Termination point

Same as recurrence 2: the textual rule "quote the formal rule, do not
paraphrase it" existed and did not prevent the class. Three entries in this
topic now; `references/rule-audit.md` disqualifies a textual artefact outright.

## Artefact

**None — build nothing, deliberately.** The mechanical rung this class needs
(a check that a comment's attributed claim appears in the cited decision file)
is semantic, not lexical: the two drifts here are a wrong symbol name and a
wrong section heading inside an otherwise correct citation, which no grep can
distinguish from a correct one. What *did* catch both was the review rung
reading the cited file, and that rung only fires when the citation resolves
to a small file. The product of this pass is therefore the citation rewrite
itself (#423/#371): every remaining `docs/decisions/` citation in source now
points at a file a reviewer can open in one `Read`, which is the precondition
for the review rung to keep catching this class.

## Sweep result

Not swept. A sweep would mean re-reading every decision citation in source
against its target, which is the review rung's job per touched file, not a
one-off. The residual `docs/DECISIONS.md` sweep that this change performed is
recorded in `docs/sessions/2026-09-11-02-issue-423-decisions-comment-sweep.md`.
